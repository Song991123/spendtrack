# SpendTrack V1 코드 규칙

작성일: 2026-04-20  
대상: SpendTrack React Publisher v1 협업용 문서

## 1. 문서 목적
- 이 문서는 현재 `src/` 기준으로 확정한 v1 코드를 두 명의 팀원이 같은 기준으로 읽고 수정하기 위한 협업 규칙입니다.
- 현재 단계는 실제 API 연동 전의 퍼블리싱/목업 데이터 기반 UI 구현 단계입니다.
- 따라서 새로운 기능을 넓히는 것보다, 구조를 이해하기 쉽게 유지하고 같은 패턴으로 화면을 확장하는 것을 우선합니다.

## 2. 현재 v1 기준 원칙
- v1의 source of truth는 `src/`입니다.
- 화면 구조는 현재 라우트 기준 10개 화면을 유지합니다.
- 데이터는 `mock` 기반으로 유지하고, 실제 서버 연동 코드는 v1 범위에 넣지 않습니다.
- 페이지 추가보다 기존 컴포넌트 재사용을 우선합니다.
- 화면을 바꿀 때는 디자인보다 정보 구조와 사용자 흐름이 먼저 깨지지 않는지 확인합니다.

## 3. 폴더 규칙
- `src/pages/<Screen>/index.tsx`
  페이지의 조립 역할만 담당합니다.
- `src/pages/<Screen>/components`
  해당 화면 전용 컴포넌트를 둡니다.
- `src/components`
  여러 화면에서 재사용하는 공통 컴포넌트를 둡니다.
- `src/styles`, `src/tokens`
  색상, 간격, 반응형 기준처럼 공통 디자인 값을 둡니다.
- `src/data`, `src/pages/*/data.ts`
  목업 데이터와 화면 표시용 가공 데이터를 둡니다.
- `src/types`
  데이터 형태를 타입으로 정의합니다.
- `src/utils`
  화면과 분리 가능한 순수 계산 로직을 둡니다.
  (CSV 파싱, 가맹점 정규화, 매칭 탐색 등도 여기에 둡니다.)
- `src/stores`
  여러 화면이 공유하는 데이터를 localStorage 기반으로 보관하는 스토어를 둡니다.
  추후 Firestore 등 원격 저장소로 교체할 때 이 레이어의 공개 API만 유지하면 됩니다.
- `public/samples`
  CSV 업로드 시연/테스트용 샘플 파일을 둡니다.

## 4. 코딩 규칙
- TypeScript 타입을 먼저 보고 컴포넌트를 작성합니다.
- 컴포넌트 이름과 파일 이름은 같게 유지합니다.
- 한 파일은 하나의 역할만 가지게 나눕니다.
- 페이지 파일은 상태 관리와 조립에 집중하고, 세부 UI는 하위 컴포넌트로 분리합니다.
- 공통 스타일 값은 하드코딩하지 말고 `tokens`를 우선 사용합니다.
- 반응형 처리는 가능한 한 기존 `media` 토큰 패턴을 그대로 사용합니다.
- 목업 데이터는 UI 검증용이므로, 의미 없는 임시 문자열보다 실제 사용 시나리오가 보이는 값으로 유지합니다.
- 라우팅 경로는 현재 확정된 경로를 유지하고, 임의로 새 메뉴를 늘리지 않습니다.

## 5. 주석 규칙
- 모든 파일 상단에는 파일의 역할을 설명하는 주석을 둡니다.
- 상태값이 2개 이상 연결되는 로직, 필터 로직, 선택 상태 전환처럼 초보자가 헷갈릴 수 있는 부분에는 블록 주석을 둡니다.
- styled-components는 "무엇을 꾸미는지" 중심으로만 설명하고 CSS 속성 하나하나를 반복 설명하지 않습니다.
- 주석은 "무슨 값이 들어간다"보다 "왜 이 블록이 필요한지"를 설명합니다.
- 코드가 바뀌면 주석도 함께 수정합니다.

## 6. UI 작업 규칙
- 페이지 레이아웃은 `AppShell`을 기준으로 맞춥니다.
- 카드, 버튼, 태그, 입력창은 공통 primitive를 먼저 재사용합니다.
- 같은 모양의 박스를 페이지마다 다시 만들지 않습니다.
- 리스트, 필터, 상세 패널처럼 반복되는 패턴은 공통화 가능성을 먼저 확인합니다.
- 새 시안이 들어와도 현재 v1 범위를 넘는 기능은 바로 추가하지 않습니다.

## 7. Git 협업 규칙
- 큰 작업 전에 먼저 현재 브랜치 상태를 확인합니다.
- 다른 사람이 수정했을 가능성이 있는 파일은 내용을 읽고 이어서 수정합니다.
- 주석 추가, 문서 수정, UI 수정은 가능하면 한 작업 단위로 커밋합니다.
- PDF, HTML 산출물은 원본 Markdown이 있으면 중복 보관하지 않습니다.
- `docs`와 `design-reference`는 "지금도 참조하는 문서만" 남깁니다.

## 8. v1에서 하지 않는 것
- 실제 OCR 연동
- 실제 로그인/회원가입 백엔드 연동
- 원격 DB 저장/조회 (localStorage 기반 임시 저장까지만 허용)
- 카드사/은행 실 API 직접 연동 (CSV 업로드로 대체)
- 소셜 로그인
- 복잡한 알림/요금제/보안 확장
- 주간/연간 분석 확장
- 분석 PDF 내보내기
- 새 메뉴 추가

## 9. 팀 운영 팁
- 페이지를 읽을 때는 `index.tsx` → `components` → `data.ts` 순서로 보면 이해가 쉽습니다.
- 수정 전에는 "공통 컴포넌트인지, 페이지 전용 컴포넌트인지"를 먼저 판단합니다.
- 새로운 아이디어가 생겨도 v1 문서에 없는 기능이면 TODO로 남기고 바로 넣지 않습니다.

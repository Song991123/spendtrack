# SpendTrack Instructor Update v3

작성일: 2026-04-20  
기준 브랜치: `main` 반영 예정 버전  
문서 성격: 강사용 진행 보고 + 현재 구현 기준 기획 업데이트

## 1. 이번 버전에서 확정한 내용
SpendTrack는 현재 **React 기반 퍼블리셔 v1을 확정한 상태**입니다.  
즉, 목업 데이터를 사용해 서비스의 핵심 사용자 흐름과 주요 화면 UI를 먼저 고정했고, 이후 백엔드/OCR/AI 연동은 다음 단계로 넘기는 방향으로 정리했습니다.

이번 정리에서 확정한 기준은 다음과 같습니다.

- 현재 프로젝트의 source of truth는 `src/`입니다.
- 현재 단계는 기능 확장보다 **구현 구조 정리, 협업 문서화, 코드 가독성 강화**가 우선입니다.
- `docs`의 기획/협업 문서와 `src` 구현 내용이 서로 어긋나지 않도록 정리했습니다.
- 기존 리디자인 산출물 중 현재 진도상 직접 유지할 필요가 없는 중복 문서는 정리 대상으로 판단했습니다.

## 6-A. 이번 단계 추가 (CSV + OCR 결합 UX)

기존 v1 확정 범위 위에 `실 데이터 반입 UX`를 현 React 구조 안에서 최소 변경으로 얹었습니다.

- 카드사 CSV 업로드 화면 (`/csv-upload`)과 `/upload`의 3번째 MethodCard 추가
- localStorage 기반 `transactionsStore` 도입, Transactions 페이지를 스토어 기준으로 전환
- OCR 편집 화면에서 주문일자 수정 가능
- OCR 저장 시 플랫폼·금액·날짜 기준 기존 거래와의 매칭 후보를 탐색하고,
  병합/신규 저장을 사용자가 모달에서 직접 선택하도록 구성
- 시연용 샘플 CSV와 포맷 설명을 `public/samples`에 포함

Firestore 등 원격 저장소는 아직 연결하지 않았으며, 스토어 공개 API는 추후 교체를 고려해 단순하게 유지했습니다.

## 7. 기능 누락 점검 결과

현재 문서상 MVP에 포함되었지만, 실제 구현이 아직 UI 수준이거나 후속 연동이 필요한 항목은 아래와 같습니다.

| 항목 | 현재 상태 | 비고 |
| --- | --- | --- |
| OCR 분석 | UI만 구현 | 실제 OCR 추출 없음 |
| 로그인/회원가입 | UI만 구현 | 실제 인증 없음 |
| 거래 저장 | localStorage 저장 구현 | 원격 DB 연동 전, 세션 간 유지는 됨 |
| 거래 수정/삭제 | 스토어 반영까지 구현 | 원격 동기화는 다음 단계 |
| CSV 업로드 | 파싱·정규화·스토어 저장 구현 | 쿠팡/네이버/무신사 3개 플랫폼 정규화 |
| OCR 결과 저장 | 스토어 저장 + 기존 거래 매칭 모달 구현 | 자동 병합 대신 사용자 선택 방식 |
| AI 인사이트 | 문구/카드 UI 중심 | 실 API 연동 없음 |

정리하면, **핵심 화면 누락보다는 실기능 연동이 아직 없는 상태**라고 보는 것이 정확합니다.

## 8. 이번 시점의 v1 결론

SpendTrack는 현재 다음 조건에서 v1로 확정 가능합니다.

1. 핵심 사용자 흐름 10개 화면이 모두 존재합니다.
2. 공통 레이아웃과 공통 UI 컴포넌트가 정리되어 있습니다.
3. 목업 데이터만으로도 서비스 구조 설명과 시연이 가능합니다.
4. 협업용 코드 규칙과 기술 요약 문서를 별도로 제공할 수 있습니다.
5. 다음 단계에서 실제 연동만 추가하면 되는 형태로 구조가 잡혀 있습니다.

따라서 이번 버전은 **"프론트엔드 퍼블리셔 v1 고정"**이라는 의미가 있습니다.
